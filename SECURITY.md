# Security Policy

Post2Drive is a hosted service (web app and Android app), not a versioned
library. Only the code currently deployed to production is supported; fixes
ship to the live service rather than as patch releases.

## Reporting a vulnerability

Please report privately. Do not open a public issue, pull request or
discussion for a security problem.

1. Go to the **Security** tab of this repository.
2. Choose **Report a vulnerability** (GitHub private vulnerability reporting).

Include what you found, the steps to reproduce it, the affected page or API
route, and the impact you expect. Test accounts you created yourself are fine
to use in a report. Please do not include other people's personal data.

## What to expect

- We aim to acknowledge a report within 5 working days.
- We aim to give a first assessment (accepted, needs more information, or
  declined with a reason) within 14 days.
- If accepted, we will fix it, tell you when it is live, and credit you if you
  want to be named.
- We ask that you give us reasonable time to fix an issue before disclosing it
  publicly.

Post2Drive is run by a very small team, so these are targets, not guarantees.

## Scope

In scope: the Post2Drive web app, its API routes, and the Android app.

Out of scope: denial-of-service or load testing, social engineering or
phishing of staff or users, physical attacks, spam, and findings that need a
rooted device or an already-compromised account.

## Good-faith research

If you act in good faith, stay within the scope above, avoid accessing or
changing other users' data, and report promptly, we will not pursue action
against you for the research.
